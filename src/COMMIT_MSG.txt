security: close password-reset token race, pin reset-otp TLS cert, guard SQL identifiers, fix static-route access logging

- reset/db.rs, token/reset_password.rs: validate and consume the
  password-reset token atomically (single LMDB read-write transaction)
  instead of two separate calls with Argon2 hashing in between. The old
  split left a real race window — two requests with the same token could
  both pass validation before either consumed it, letting the token be
  used twice.

- cli/prompt.rs: `reset-otp`'s loopback admin connection now pins to the
  server's own certificate (`tls_certs_only` + hostname-mismatch
  tolerance) instead of accepting any certificate whatsoever
  (`danger_accept_invalid_certs`). Falls back to the old behavior, loudly
  warned, only if the certificate can't be read.

- databases/db.rs: `load_values_for_user` now checks its `table`/`column`
  arguments against an explicit allow-list before building the query
  string. Both real call sites already passed only hardcoded values, so
  this doesn't change behavior — it just makes that safety a property of
  the function itself rather than an invariant every future caller has
  to remember to preserve.

- network/proxy.rs: static routes (`static:`/`static_index:`) now log the
  authenticated username/token-id, matching the proxied-route handlers.
  `check_static_auth` correctly enforced `required_login` already, but
  discarded the resolved identity instead of passing it to
  `LogContext::set_user` — the access log's `[username]`/`[tid]` fields
  showed `-` for every static route regardless of login state.

- config/def_config.rs, reset/db.rs: removed three now-dead functions
  (`ensure_running_as_proxyauth`, and the old `validate_token`/
  `consume_token` pair superseded by the atomic fix above). Kept them
  around briefly as compatibility shims; removed rather than
  `#[allow(dead_code)]`-suppressed since leaving the old
  validate-then-consume pair in place risked a future caller
  reintroducing the exact race this fixes.
